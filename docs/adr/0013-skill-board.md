# 技能看板：同一屏内启用与禁用，勾选状态即提交态

`enable` 与 `disable` 的交互式路径是两个各自为政的选择器（先选 Source 再选技能 / 只列已声明技能），换掉一个技能要在两条命令之间来回，既看不到「这一 Scope 现在到底声明了什么」，也看不到换源的代价。新增 `skill-manager board`：一屏列出当前 Scope 的全部技能，行 = 一条可声明的技能，空格切换，Enter 提交，Esc 取消；勾选后的整体状态就是目标声明态——新勾选即 enable，取消勾选即 disable，同名换行即换源，「什么都没改就 Enter」不写盘。`enable` / `disable` 的非交互路径不动：它们的 JSON 契约（无参 `disable` 在非 TTY 下返回空 `results`）被脚本依赖，而看板只能在 TTY 里出现，所以看板是**新增命令**而不是改写两个既有命令的默认行为（拒绝的替代方案：让无参 `enable` / `disable` 打开同一屏——省一个动词，但把两个既有命令的非 TTY 行为改坏，同一动作还会多出两个入口）。

**行模型。** 行来自「缓存中所有 Source 的技能 + 本 Scope 的声明」，按 Source 分节；已声明但缓存中已不存在的技能落到 `declared · not in cache` 尾节，其唯一有意义的动作是取消勾选。声明按 `(repo, path)` 与缓存技能配对，配对成功时行名取声明里的 `name`——名字是声明的主键，不能让缓存里的 FM name 抢走。缓存扫描默认跳过 hidden / `metadata.internal` 技能，但**已声明的**这类技能仍按磁盘上的 `SKILL.md` 出行（否则一个用 `enable --all` 启用过的技能会在看板上假装「不在缓存」）。跨 Scope 事实用两个符号：`⊕` 同源全局重叠（良性），`⚠` 异源跨 Scope 冲突（必须处理）；本 Scope 的链接状态不用符号，写成行尾的词（`link broken` / `not linked` / `link outside this manager`），因为符号要配图例而词自解释。提示符上的 `unsaved +N −M` 是唯一的变更预览，不另设常驻 diff 面板：看板本身就是被修改的状态，diff 只是它的差分，多一块面板等于同一信息说两遍。

**提交原子性。** 勾选状态先归一化成 `BoardPlan`（`enable` / `disable` 两批）；任一同名行被同时勾选、或新 enable 与另一 Scope 的不同源同名声明冲突，都在任何写盘之前拒绝整批——看板只能改一个 Scope，跨 Scope 冲突不是它解决的地方，它只告诉你该跑 `skill-manager --global disable <name>`（或反向）。校验通过后先删后加、一次性写入声明文件：同名换源因此不会出现「先删掉、再写失败」导致该名字从盘上消失的中间态；随后只为新启用的技能准备 Source（只 clone 不 pull，沿用 ADR 0004）并建链接。Esc 取消不写任何东西；缓存与声明的扫描全部在提交前完成，因为提交期间不再有交互点。

**拒绝的替代方案**：①「四符号标记（⊕ / ⚠ / ↯ / ?）配图例」——屏幕没有常驻图例位，四个符号没人读，其中「缓存缺失」已由节标题说过一遍；②「常驻 diff 面板」——见上；③「空格即写盘」——一次误触就改配置，换源还会短暂出现同名两条声明；④「同名勾选时拒绝、要求先取消旧行」——换源是高频动作，自动取消旧行少两次按键，而校验层仍会兜住异常路径；⑤「平铺列表（按名字排序、Source 内联）」——实测分节更容易扫到目标，也天然把「这个技能的来源」放在标题而不是每行重复。
